## 1. 射频 TX/RX 切换链路（已实物确认 U4 短接）

### 1.1 实际拓扑

```
                    ┌──────────────────────────────────────────┐
   E22-900M33S      │                                          │
   U2.8 DIO2 ───────┼─── U4 (2-pad 跳线, 29.083/66.770, 底层) ──┼──> U2.7 TXEN
                    │                                          │
                    └─── U3.2 (A, 施密特输入)                  │
                              U3 = SN74LVC1G14DBVR (SOT-23-5)   │
                              U3.4 (Y, 输出) ───────────────────┼──> U2.6 RXEN
                              U3.5 VCC ← ESP_3V3 (U1.36)       │
                              U3.3 GND                          │
                              U3.1 NC                           │
```

### 1.2 逻辑真值表（U4 短接时）

| DIO2 (SX1262) | TXEN (pin7) | RXEN (pin6) | E22 射频开关 | 发射/接收 |
| --- | --- | --- | --- | --- |
| 高 | **1** | 0 | 切到发射 | TX ✅ |
| 低 | 0 | **1** | 切到接收 | RX ✅ |
| 复位/悬空 | 0（经 U4） | 1（U3 输出高） | 切到接收 | 默认 RX，可接受 |

**结论：互斥且完整，两个状态都有效，不存在"两个都为 0 导致射频开关关闭"的情况。**

### 1.3 电平与极性核对

- E22 datasheet 明确：pin6 = RXEN，pin7 = TXEN，**均为高电平有效**；pin7 注明"连接外部单片机 IO **或 DIO2**"。
- 已核对网表：`RADIO_TXEN` → U2.7 + U4.2；`RADIO_RXEN` → U2.6 + U3.4；`RADIO_DIO2` → U2.8 + U3.2 + U4.1。与 datasheet 完全一致。
- **SN74LVC1G14DBVR 引脚定义（TI SCES218）**：pin1 = NC，pin2 = A（输入），pin3 = GND，pin4 = Y（输出），pin5 = VCC。
  原理图标注 `1 NC / 2 A / 3 GND / 4 Y / 5 VCC` 与此一致。**NE555 式误接的可能性排除。**
- 电平匹配：U3 由 `ESP_3V3` 供电，输入阈值按 3.3 V 轨计算，SX1262 的 DIO2 输出同为 3.3 V 逻辑 —— 匹配，且施密特输入抗抖动。**不需要电平转换。**

### 1.4 固件的唯一要求

必须执行 `SetDio2AsRfSwitchCtrl(1)`（RadioLib 里是 `radio.setDio2AsRfSwitch(true)`），让 SX1262 把 DIO2 当射频开关控制脚驱动。

⚠️ **如果这一步漏了**，DIO2 不会被芯片驱动，TXEN/RXEN 就是静止电平 → 模块停在软件关断（约 2 µA），表现为"完全收不到、也发不出去"。这正是需要"手动切换"的根因。

## 2. 电源架构

### 2.1 实际拓扑（已从飞针数据逐脚确认）

```
USB-C 母座 ──> PD1 (PDC004-PD诱骗模块, PD1.2) ──┐
                                                ├──> $1N26 ──> D1.1 [SS54]
DC-005-A200 (DC1.1, 中心正) ────────────────────┘                  │
H2.1 (LAIL-PZ2.54-2P, 备用输入) ──> VCC ──────────────────────────┘
                                                     D1.2 = VCC
                                                          │
                                        ┌─────────────────┴──────────────────┐
                                        │  U16 (MP2482 降压模块)             │
                                        │  U16.1 = VCC   U16.4 = +5V         │
                                        │  U16.2/3 = GND                     │
                                        └─────────────────┬──────────────────┘
                                                          │
                                          +5V 域
     U17 16V/470µF, U5 22µF, C1 100nF, U18/U19/U20 10µF ×3
     U2.9 + U2.10  E22-900M33S   ← 2 W 发射，峰值 ~1200 mA（原设计按 30S 的 650 mA 评估）
     U6.1          ATGM336H GNSS
     U7.1          GY-BMI160          ← 模块自带 LDO 的输入
     U10.1         PCF8563 RTC 模块   （1.0–5.5 V，5V 合法）
     U13.1         OLED 0.96"         ← 经 U15 焊桥，见发现 2-2
     U1.39         ESP32-S3-Pico VBUS

   ★ 3.3V 域（U7 模块内的 LDO 产生）
     U7.2 = BMI_3V ──┬──> U12 焊桥 ──> $1N126 ──> U11.1 (GY-BMP280 VCC)
                     └── （BMI160 传感器自身供电）

   ESP_3V3 域：U1.36 (3V3 OUT) ──> U3.5 (反相器 VCC)     仅此一个负载
```

**关键点：`BMI_3V` 是 GY-BMI160 模块自己那颗 LDO 的输出（3.3 V），经焊桥 `U12` 送到 GY-BMP280。**
BMP280 拿到的是 3.3 V，在 1.71–3.6 V 工作范围之内，**不是 5 V**。

### 2.2 关键发现

**🟢 发现 2-1（已澄清）：`U11` (GY-BMP280) 由 BMI160 的 3.3 V LDO 供电 —— 合规**

初版复核把 `U12` 误读成"从 +5 V 取电的跳线"，据此报了一个 P0 超压问题。**这个结论是错的，已撤回。**

从飞针测试数据逐脚核对，实际网络是：

| 焊盘 | 网络 | 说明 |
| --- | --- | --- |
| `U12_1` | `BMI_3V` | 焊桥的公共端 = BMI160 LDO 输出 |
| `U12_2` | `$1N126` | ─┐ |
| `U11_1` | `$1N126` | ─┘ GY-BMP280 的 VCC |
| `U7_2` | `BMI_3V` | GY-BMI160 的 3V3 脚 |

即 `BMI_3V ──[U12 短接]── $1N126 ──> U11.1(BMP280 VCC)`。全程没有 `+5V` 参与。

- BMP280 datasheet：工作 **VDD 1.71–3.6 V**，绝对最大 **4.25 V** → **3.3 V 完全合规**。
- 旁证：Altium 源文件 `PCB/Altium_T-mesh_2026-09-06.zip!P1.schdoc` 里 `BMI_3V` 这个网络名出现 4 次，
  与飞针数据一致。

> ⚠️ **一条设计上的实践提示（不是缺陷）**：这是"用一颗模块的 LDO 输出带另一颗模块的 LDO 输入"
> 的级联结构。GY-BMP280 若为板载 LDO 版本，其 SPX3819 在 3.3 V 输入下压差余量很小（约 0.1–0.2 V），
> 输出会略低于 3.3 V；BMP280 电流仅 ~0.7 mA，实际影响可忽略。
> 唯一需要留意的是 BMI160 那颗 LDO 的总电流预算（现在要同时供 BMI160 + BMP280）。

**🟡 发现 2-2：OLED 的供电焊桥 `U15`，以及 I2C 上拉基准**

`GPIO17`(SDA) / `GPIO18`(SCL) 挂了四个从设备，但它们的电源来源**并不相同**：

| 从设备 | 供电来源 | 供电轨 |
| --- | --- | --- |
| U7 GY-BMI160 | `+5V`（模块内 LDO 降到 3.3 V） | 5 V 输入 |
| U11 GY-BMP280 | `BMI_3V`（BMI160 的 LDO 输出） | **3.3 V** |
| U10 PCF8563 | `+5V` | 5 V（芯片 1.0–5.5 V，合法） |
| **U13 OLED** | `$1N132` ← 焊桥 `U14`（GND）/ `U15`（+5 V） | **5 V** ⚠️ |

**`U13`（OLED）被 `U15` 焊桥接到了 `+5V`。** 多数 4-pin 0.96" OLED 模块**没有板载 LDO**，
标称供电 3.3 V（SSD1306 绝对最大约 4.0 V），5 V 属于超规。

要确认/处理的话：
1. 量 OLED 模块 VCC 与 SDA/SCL 的静态电压。若 SDA/SCL 被上拉到 ≥4.5 V，则它内部是 5 V 轨。
2. 该上拉会把 5 V 灌到同一总线上的 **GY-BMP280（现由 3.3 V 供电）** 和 **ESP32-S3 的 3.3 V GPIO**（IO 绝对最大约 3.6 V）。
3. **首选改法**：把 `U15` 焊桥改到 3.3 V 一侧。板上 `ESP_3V3`（`U1.36` 3V3 OUT）目前**只带一颗反相器**，
   带一颗 OLED（典型 10–20 mA）余量充足。
4. 或者：确认该 OLED 模块自带 LDO（部分带 "KB33"/"662K" 字样），则可保留 5 V。

**🟢 发现 2-3（已澄清）：PD → DC 是有意设计**

`$1N26 = {PD1.2, D1.1}`，`VCC = {D1.2, DC1.1, H2.1, U16.1}`。
初版据此认为"PD 与 DC 直接并联缺隔离"。

**这不是缺陷，是设计意图。** 依据：`PCB/ProPrj_T-mesh_2026-09-06.epro2` 解出的
EasyEDA 源码里，顶面丝印文本记录明确含 **`"PD -> DC"`**（`FONT` 记录，
`["PD -> DC","Consolas Italic",...]`），另有一条 `"7-20V"` 输入范围丝印。

也就是说：USB-C（PD 诱骗出 12 V）与 DC 座在 `$1N26` 汇合，经 `D1`(SS54) 后成为 `VCC`，
**PD 口与 DC 口在板上是同一个电源节点的两个入口**，方向性由 SS54 和外部接线决定。
按设计意图使用时无需改动。

> 已从修改清单中移除该条。

**🔴 发现 2-4（新，来自 EasyEDA 源码）：`.epro2` 里捆了不止一块板子**

解压 `PCB/ProPrj_T-mesh_2026-09-06.epro2` → `T-mesh.epru`（6.5 MB，`||` 分隔的 JSON 记录流）
后，里面同时存在**两套完整的原理图网络集**和**两套丝印**：

| | 设计 A = **本仓库这块板** | 设计 B |
| --- | --- | --- |
| 主控 | **ESP32-S3-Pico** | **nRF52840 SuperMini** |
| 射频 | **E22-900M33S** | **E22-400M30S** |
| 网络命名 | `RADIO_*` + `GPIO*` + `BMI_3V` + `ESP_3V3` | `DIO1/BUSY/NRST/MISO/MOSI/SCK/NSS/RXEN` + `BAT_IN` + `BACKUP_BAT` |
| 丝印 | `T-Meshtatics` / `Designed by Tacoin` / `PD -> DC` | `SimpleMesh V0.1` / `+` / `-` / `7-20V` |
| 工程描述 | — | 「SimpleMesh V0.1 … 48×55mm … nRF52840 SuperMini + ATGM336H 5N31 + E22 400M30S」 |

也就是说 `.epro2` 的 **`project2.json` 描述的是设计 B（SimpleMesh / nRF52840）**，
而 `T-mesh.epru` 里还含设计 A（本板）。**打开这个工程时看到的标题/描述不能代表本板。**

**好消息**：已核对 `PCB/Altium_T-mesh_2026-09-06.zip!P1.schdoc`，其内容**是本板**：
`ESP32-S3-Pico` ×5、`E22-900M30S` ×9、`SN74LVC1G14` ×6、`PDC004` ×6、`GY-BMP280` ×5、`BMI_3V` ×4，
且 `nRF52840` / `E22-400M30S` 均为 0 次。Gerber 包同理（含 `E22-900M30S` 封装、
`FlyingProbeTesting.json` 的网络与 [Netlist](PCB/Netlist_Schematic1_1_2026-10-14.tel) 完全吻合）。

**所以要小心的只是 `.epro2`。** 建议从中明确导出/另存本板工程，避免后续导出 Gerber 时选错设计。

**🟢 发现 2-5：`+5V` 这级的储能容量够，但电流余量要重新核算**

2 W 发射峰值约 **1200 mA**（E22-900M33S 规格；原设计是按 30S 的 650 mA 评估的），脉冲式。`+5V` 上挂了 `U17` 470 µF/16 V + `U5` 22 µF + `U18/U19/U20` 10 µF ×3 + 6 颗 100 nF。耐压余量很大（16 V vs 5 V），储能充沛；但 **650 → 1200 mA 是接近两倍**，需确认 MP2482 的限流设定与电感饱和电流、以及 5 V 走线宽度。**脉冲能量不是问题，持续电流能力才是。**

**🟢 发现 2-6：T-Beam 电池部分根本没接**

`U1` 的 `VBUS`(pin39/40) 接了 +5 V，`VSYS`(pin38/pin37) 未使用。**全板没有电池/power-path**，纯 12 V 供电。做"基站"合理，但如果你之后想加电池，需要额外设计。

> 对比：EasyEDA 工程里的设计 B（SimpleMesh/nRF52840）**有** `BAT_IN`、`BACKUP_BAT`、`MS621FE` 后备电池等网络与器件；
> 本板（设计 A）没有。两者不要混淆。

## 3. GPIO 分配核对

### 3.1 实际接线（从网表 + 飞针数据双重确认）

| ESP32-S3 | 网络 | 对端 | 说明 |
| --- | --- | --- | --- |
| GPIO1 | RADIO_DIO1 | U2.13 | E22 DIO1 |
| GPIO4 | RADIO_BUSY | U2.14 | E22 BUSY |
| GPIO5 | RADIO_NRST | U2.15 | E22 复位，低有效 |
| GPIO10 | RADIO_CS | U2.19 | E22 NSS |
| GPIO11 | RADIO_MOSI | U2.17 | 到射频 |
| GPIO12 | RADIO_SCK | U2.18 | SPI 时钟 |
| GPIO13 | RADIO_MISO | U2.16 | 来自射频 |
| GPIO6 | GPS_PPS | U6.5 | GNSS 秒脉冲 |
| GPIO7 | GPS_WAKEUP | **H1（1P 排针）** | ⚠️ 见 3.3 |
| GPIO8 | GPS_TX | U6.3 | ESP32 收 |
| GPIO9 | GPS_RX | U6.4 | ESP32 发 |
| GPIO17 | SDA | U7.5, U10.3, U11.4, U13.4 | I2C 数据 |
| GPIO18 | SCL | U7.4, U10.4, U11.3, U13.3 | I2C 时钟 |
| GPIO14 | RTC_INT | U10.6 | PCF8563 中断 |
| GPIO33 | IMU_INT | U7.10 | BMI160 INT1 |
| **DIO2** | RADIO_DIO2 | U2.8, U3.2, U4.1 | **射频开关控制，非 MCU GPIO** |

### 3.2 未使用的引脚

以下在网表里是**孤立单点网络**，即预留/空焊盘，固件里可当空闲脚用：
`GPIO2`、`GPIO15`、`GPIO16`、`GPIO34`、`GPIO35`、`GPIO36`、`GPIO37`、`GPIO38`、`GPIO39`、`GPIO40`、`GPIO41`、`GPIO42`

**⚠️ `GPIO35/36/37` 并不接 BMI160 的 SPI。** 整块板上 BMI160 走的是 **I2C**（`U7.4/U7.5` = GPIO18/GPIO17），中断在 `GPIO33`。README 第 133–135 行写的 "IMU SPI MOSI/SCK/MISO = GPIO35/36/37" **与实际不符**，需修正。

### 3.3 两处需要留意

**`GPIO7` → `H1`**：`GPIO7` 只连到 `U1.31` 和 `H1.1`，**没有连到 ATGM336H**（`U6` 只用了 1/2/3/4/5 脚）。所以 GPIO7 目前是"引到一个 2.54 mm 排针的备用 IO"，不是真的 GPS 唤醒线。README 标成 `GPS WAKEUP` 偏乐观。

**ATGM336H 只用了 5 个脚**：`+5V / GND / TX / RX / PPS`，**没有 WAKEUP 脚**。如果你需要 GPS 休眠控制，得换带 WAKEUP 引脚的 GNSS 模块。

**OLED 用了 4 根线**：`U13` 引脚 1/2 = `+5V`/`GND`，3/4 = GPIO18/GPIO17，5/6/7/8 是网表自动生成的 `NET_14..NET_17`（未布线，只存在于符号上）。也就是说 **OLED 只用了 4-pin 的 I2C 接口**，和 README 的描述一致。但注意：4-pin 的 0.96" OLED 模块**丝印顺序不统一**，`VCC/GND/SDA/SCL` 的顺序各厂家不同，插之前务必核实。

## 5. 复核方法与可复现性

本次复核**不是靠读 PDF 猜的**，多条独立证据链互相验证：

1. **网表**：`Netlist_Schematic1_1_2026-10-14.tel`，76 行，含全部 41 个元件和全部网络。

### 5.1 我怎么把 BMP280 那条搞错的（供后续复核参考）

教训：**光看网表里的网络名不够，要看焊桥的哪一端是公共端。**

`$1N126` 这个网络同时接到 `U11.1`(BMP280 VCC) 和 `U12_2`，
而 `U12_1 = BMI_3V`。我当初想当然认为"焊桥是从 +5V 取电的跳线"，
**没有回头去查 `BMI_3V` 这个网络名接的是谁**。查一下就会发现 `BMI_3V` 就是 `U7_2`，
即 GY-BMI160 模块的 3V3 输出脚 —— 命名本身已经说明了它是 BMI160 出来的 3.3 V。

**正确做法**：对任何"某器件供电来自 X"的结论，都要把 X 这个网络**穷举其所有焊盘**，
再确认每个对端是什么。只看单一焊盘会得出片面的结论。
